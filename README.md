## Alg_BOOT — алгоритм бута

Реализация **алгоритма Бута** (Booth's algorithm) — классического способа умножения двух чисел со знаком в дополнительном коде, который позволяет сократить число операций сложения/вычитания за счёт анализа пар соседних битов множителя.

**Идея алгоритма:**
1. К множителю справа добавляется дополнительный (вспомогательный) нулевой бит.
2. Множитель анализируется парами соседних бит `(bi, bi-1)`:
   - `01` → к аккумулятору прибавляется множимое (+M);
   - `10` → из аккумулятора вычитается множимое (−M);
   - `00` или `11` → действие не выполняется.
3. После каждого шага выполняется арифметический сдвиг вправо (accumulator + multiplier) на 1 разряд.
4. Шаги повторяются по числу разрядов множителя; результат — произведение в удвоенной разрядности.

Такой подход эффективно обрабатывает последовательности единиц во множителе, сокращая количество операций сложения по сравнению со сдвиговым умножением.

**Что внутри:** HDL-описание конечного автомата умножителя Бута (регистры множимого/множителя, аккумулятор, счётчик итераций, логика сложения/вычитания и арифметического сдвига).

## FIFO — сдвиговый и кольцевой буферы

Один из первых учебных проектов репозитория. Реализованы два классических варианта аппаратной очереди FIFO (First In, First Out):

| Вариант | Принцип работы | Особенности |
|---|---|---|
| **Сдвиговый FIFO** | Данные при каждой записи физически сдвигаются по регистрам к выходу | Проще в реализации и отладке, но менее эффективен по энергопотреблению и площади при большой глубине очереди |
| **Кольцевой FIFO** | Данные хранятся в статической памяти (регистровый файл/RAM), а перемещаются лишь указатели чтения (`rd_ptr`) и записи (`wr_ptr`) по кругу | Экономичнее по ресурсам при росте глубины, требует логики сравнения указателей для флагов `full`/`empty` |

Общая функциональность обеих реализаций:
- запись/чтение по тактовому сигналу с флагами `full` и `empty`;
- защита от переполнения и чтения из пустой очереди;
- параметризация по разрядности данных и глубине буфера.

## Real_Mul — вещественный умножитель

Аппаратный умножитель чисел с плавающей точкой:

1. **Распаковка операндов** — выделение знака, порядка (экспоненты) и мантиссы каждого из чисел, обработка особых случаев (ноль, денормализованные числа, `NaN`/`Inf`).
2. **Вычисление знака результата** — XOR знаковых битов операндов.
3. **Сложение порядков** с учётом вычитания смещения (bias).
4. **Умножение мантисс** как целых чисел фиксированной точки.
5. **Нормализация результата** — сдвиг мантиссы и коррекция порядка, если после умножения произошло переполнение разрядной сетки.
6. **Округление** результата до требуемой разрядности мантиссы.
7. **Упаковка результата** обратно в формат с плавающей точкой.

Проект демонстрирует работу с форматом чисел с плавающей запятой на уровне RTL и обработку граничных случаев арифметики IEEE 754.

## UVM_VENDING_MACHINE — UVM-верификация вендингового автомата

Проект по функциональной верификации DUT «вендинговый автомат» с использованием методологии **UVM** на SystemVerilog.

DUT принимает монеты/купюры, отслеживает внесённую сумму, проверяет достаточность средств для выбранного товара, выдаёт товар и сдачу (либо сообщает об отказе при недостатке средств).

**Компоненты тестового окружения (testbench):**
- **Sequence / Sequence Item** — генерация случайных и направленных сценариев (разные номиналы монет, разные товары, граничные суммы);
- **Driver** — подача стимулов на интерфейс DUT;
- **Monitor** — пассивный съём сигналов с интерфейса DUT;
- **Agent / Environment / Test** — стандартная иерархия компонентов UVM, объединяющая всё вышеперечисленное.
